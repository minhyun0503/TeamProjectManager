# 팀프로젝트 관리 프로그램 — 피드백 반영·브리핑 학습 버전

**파일을 열어 하나씩 설명하는 브리핑은 [팀원별 소스 브리핑](docs/member_briefings/README.md)을 사용하세요.** 개인 HTML에는 전체 코드·줄 강조·구간별 설명, 개인 PDF에는 같은 설명을 담았습니다.

**처음 읽는 조원은 [쉽게 읽는 설명서](docs/easy/index.md)부터 보세요.** 공통 1장과 본인 담당 1장을 먼저 읽는 구성이고, [6장 PDF](output/pdf/team_project_briefing.pdf)와 [한 파일로 읽는 HTML](docs/easy_guide.html)을 제공합니다.

이 브랜치에는 피드백 반영 프로그램 **TeamProjectManagerFeedback 하나만** 있습니다. 저장소 루트의 `.project`를 기준으로 Eclipse에서 가져오면 됩니다. 기존 작성본은 `main`과 `refactor/member-packages` 브랜치 및 이전 커밋에 보존되어 있습니다.

## 바로 실행

1. **Eclipse IDE 2023-12 + Java 17 기준**입니다. JDK 17 또는 21을 사용하고 `java -version`, `javac -version`으로 확인합니다. 프로젝트의 소스·출력 버전은 17로 고정했습니다.
2. Windows에서는 `run.bat`, macOS/Linux에서는 `sh run.sh`를 실행합니다.
3. **로컬 데모**를 선택합니다. 인터넷이나 MySQL 서버 없이 실행됩니다.
4. 아이디 `demo1`~`demo5`, 비밀번호 `demo1234`로 로그인합니다.
5. `demo1`·`demo2`는 팀 7·42 중 선택할 수 있습니다. 다른 계정은 팀 7만 사용합니다.

데모 DB는 사용자 홈의 `.teamproject-feedback/demo.mv.db`에 저장됩니다. 프로그램을 다시 열어도 데이터가 유지됩니다. 모든 창을 종료하고 이 데모 파일을 별도로 옮기면 새 데모 DB로 다시 시작할 수 있습니다. 원래 Aiven DB에는 연결하지 않습니다.

Eclipse: `Import → Existing Projects into Workspace → 저장소 루트 폴더`을 선택하고 `src/teamproject/common/Main.java`를 실행하세요. 프로젝트 이름은 `TeamProjectManagerFeedback`입니다. 프로젝트 설정에 `JavaSE-17`, Compiler 17, UTF-8을 포함했습니다. JRE 오류가 있으면 [Eclipse 2023-12 설정 안내](docs/09_eclipse_2023_12.md)를 참고하세요. `schema.sql`도 빌드 출력 폴더로 복사되어야 합니다. 제공한 build 스크립트는 이 작업을 수행합니다.

MySQL로 여러 PC에서 사용할 때는 새 전용 DB에 `db/mysql_demo.sql`을 한 번 실행한 뒤, 시작 화면에서 DB 주소·사용자·비밀번호를 입력합니다. SQL 스크립트가 스키마와 가상 계정 demo1~demo5를 준비합니다. 시작 코드 자체는 MySQL에 계정을 자동 생성하지 않습니다. 원본 DB `team_project`를 그대로 사용하는 방식은 제공하지 않습니다. MySQL 실서버 연결은 이 작업 환경에서 검증하지 않았습니다.

## 기능

| 구분 | 제공 기능 | 사용 위치 |
|---|---|---|
| 기존 기반 | 로그인·팀 선택, 팀원 CRUD, 업무 CRUD, 개인·전체 진행률, 자료 링크, 대시보드 | 기존 관리 탭 |
| 실시간 메모장 참고 | 공유 메모 CRUD, 작성·수정자, 버전 검사, 내용 이력, 3초 자동 갱신 | 공유 메모 |
| 노션 참고 | 상태별 업무 카드, 내 업무만 보기, 마감일 정렬, 메모에서 업무 생성·원문 연결 | 업무 보드·공유 메모·업무 관리 |
| 패들렛 참고 | 아이디어 카드, 참고 링크, 댓글, 1인 1공감/취소, 5초 자동 갱신 | 아이디어·댓글 |
| 기존 계획 완성 | 일정 CRUD, 월간 달력, 여러 달에 걸친 일정과 업무 마감일 표시 | 일정·달력 |
| 최근 활동 | 메모 저장, 일정 저장, 아이디어 저장·댓글·공감 기록 | 최근 활동 |

자동 갱신은 DB를 주기적으로 조회하는 **폴링**입니다. 글자 단위 동시 편집이나 WebSocket 푸시는 아닙니다. 업무 카드는 선택 후 상태 변경 버튼으로 옮깁니다. 실시간 채팅, 파일 업로드·미리보기, 팀 생성·초대는 구현 범위에 포함하지 않습니다. 자료는 링크를 저장합니다. 최근 활동은 위 표에 명시한 동작을 기록하며, 기존 업무·팀원 CRUD와 삭제 동작 전체를 추적하는 감사 로그는 아닙니다.

## 역할과 브리핑 책임

PPT의 담당 영역을 유지하고, 새 기능을 같은 영역에 추가했습니다. **각 파일의 최종 브리핑 책임자는 한 명**입니다. 공개 저장소의 기존 이름 표기를 유지했습니다.

| 담당자 | 기존 역할 | 추가 역할 | 설명파일 |
|---|---|---|---|
| 장*민 | DB·JDBC·공통 시스템 | 독립 데모 실행, 확장 스키마, 소속 팀 검사, 활동 기록 DAO | [공통·DB](docs/02_common.md) |
| 이*찬 | 로그인·팀원 관리 | 공유 메모, 자동 갱신, 수정 충돌 검사·이력 | [로그인·공유 메모](docs/03_member.md) |
| 윤*훈 | 업무 관리 | 상태별 보드, 내 업무, 메모→업무 생성과 원문 연결 | [업무 관리](docs/04_task.md) |
| 이*주 | 일정·진행률 | 일정 CRUD·월간 달력, 기간 겹침 계산·업무 마감일 표시 | [일정·진행률](docs/05_schedule.md) |
| 신*준 | 자료·대시보드 | 아이디어 카드·댓글·공감, 최근 활동 화면, 통합 탭 | [자료·협업](docs/06_resource.md) |

전체 파일·메서드별 책임과 코드 위치는 [코드 색인](docs/07_code_index.md)을 기준으로 합니다. 루트의 기존 버전에 포함됐던 팀장의 열 너비 통합 등 공동 기여는 유지하며, 확장 버전 `TaskFrame`의 최종 브리핑은 업무 담당자가 맡습니다.

## 검증과 의존성

- `test.bat` 또는 `sh test.sh`: H2 MySQL 호환 모드 회귀 검사 **65개** (기존 기능 52개 + 달력 13개).
- `tests/ReviewGuiTest.java`: 느린 조회 중 사용자가 바꾼 선택 유지, 팀에서 나간 담당자의 임의 재배정 방지를 확인합니다.
- `tests/GuiSmokeTest.java`: 디스플레이 환경에서 9개 탭과 다른 연결의 메모·아이디어 자동 갱신을 검사하고 스크린샷을 저장합니다. 일반 회귀 검사와 별도로 실행합니다.
- Java 17 소스·타깃으로 전체 컴파일하고 실제 JDK 17에서 회귀·화면·시작 흐름을 검증했습니다. Java 25를 요구하지 않습니다.
- `tests/StartupSmokeTest.java`: 실제 Main의 모드 선택→파일 DB 준비→로그인→팀 선택→통합 화면을 검사합니다.
- 실제 MySQL 서버·두 대의 물리 PC 연결은 별도 확인 대상입니다. 두 JDBC 연결의 버전 충돌과 화면 자동 갱신을 로컬 환경에서 검증합니다.
- JDBC 드라이버: `lib/mysql-connector-j-26.10.0.jar`(기존 포함본), `lib/h2-2.4.240.jar`(데모·테스트). 드라이버의 배포 고지는 각 JAR의 META-INF 및 [의존성 안내](docs/dependencies.md)를 참고하세요.

코드 재점검 결과와 확인 범위: [검사 기록](docs/code_review.md).
