# 자바 기초 수준 코드 판단

인터페이스까지 배웠다면 객체 생성·상속·조건문·반복문이 중심인 부분은 바로 따라가기 쉽습니다. 로그인 결과에서 팀 번호를 읽거나, 업무를 상태별로 나누거나, 완료 건수를 세는 코드가 좋은 시작점입니다. Swing의 이벤트 호출 순서, JDBC로 쓰는 SQL, 백그라운드 조회와 트랜잭션은 자바 기초 문법과 별도로 짧은 설명이 필요합니다.

| 코드 | 읽기 어려웠던 부분 | 바꾼 흐름 |
|---|---|---|
| Main | 시작 메서드에 실행 방식 선택, DB 설정, 대기창, 연결 작업이 몰려 있었음 | start에서 어떤 설정과 작업을 호출하는지 먼저 읽고, 실제 DB 준비는 DatabaseStartupWorker에서 확인 |
| NotePanel·IdeaPanel | 익명 작업 클래스 안에서 DB 조회와 화면 결과 처리까지 따라가야 했음 | 이름을 붙인 작업 클래스의 조회와 완료를 읽고, updateList에서 목록 갱신과 선택 복원 확인 |
| NoteDAO | save 안에서 등록·수정 SQL과 이력 저장까지 한꺼번에 처리했음 | save에서 판단·호출·확정을 읽고, 각 SQL은 insertNote·updateNote·insertHistory에서 확인 |
| TaskBoardPanel | 목록 선택 해제와 카드 상태 분류를 중첩된 한 줄 조건으로 읽어야 했음 | 선택 해제와 선택 조회에 이름을 붙이고, 반복문의 칸과 카드에 이름을 붙여 구분 |
| SchedulePanel | reload에서 자료 조회와 달력·표 표시를 모두 담당했음 | reload → drawCalendar → fillScheduleTable 순서로 확인 |
| MainFrame | 탭 변경 리스너가 여러 곳에 흩어져 있었음 | ChangeListener 구현과 stateChanged 한 곳에서 새로고침 대상을 확인 |

SwingWorker에는 화면을 멈추지 않고 느린 DB 조회를 처리하는 역할이 있습니다. 트랜잭션은 메모와 수정 이력을 같이 확정해야 하는 이유를 설명할 때 필요합니다. 각 개인 자료에서 해당 용어를 사용하는 코드 옆에 뜻을 붙였습니다.

Java 17에서 기존 기능 검사 52개와 달력 검사 13개가 통과했습니다. 화면 검사에서는 로컬 DB 초기화·로그인·팀 선택, 9개 탭 열기, 메모·아이디어 자동 갱신과 조회 중 선택 유지, 팀에서 나간 담당자의 업무 수정창을 확인했습니다. 실제 MySQL 서버에서는 실행을 확인하지 못했습니다.
