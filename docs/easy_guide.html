모두 먼저 읽기

공통 1장 · 화면 부품과 코드 읽는 법

화면은 입력을 받고, 자바 코드는 처리 순서를 정하고, 저장소(DB)는 결과를 기억합니다. 본인 담당 장을 읽기 전에 아래 부품부터 확인하세요.

코드에 나오는 화면 부품

이름화면에서 하는 일
JFrame / JPanel프로그램 창 / 창 안에서 버튼과 글자를 묶는 영역
JLabel / JButton내용을 보여 주는 글자 / 눌러서 일을 시키는 버튼
JTextField / JTextArea한 줄 입력칸 / 여러 줄 입력·표시 칸
JList메모 제목처럼 항목을 세로로 나열하는 목록. 하나를 누르면 해당 항목을 선택합니다.
DefaultListModelJList에 보여 줄 내용을 보관하는 목록. 보관 목록이 바뀌면 화면 목록도 바뀝니다.
JTable / DefaultTableModel행·열이 있는 표 / 그 표에 표시할 내용을 보관하는 목록
JComboBox / JCheckBox펼쳐서 하나를 고르는 선택칸 / 켜고 끄는 확인칸
JScrollPane / JTabbedPane내용이 길면 스크롤하는 영역 / 화면을 골라 여는 탭

JList는 이렇게 연결합니다

DefaultListModel<NoteDAO.Note> model = new DefaultListModel<>();
JList<NoteDAO.Note> list = new JList<>(model);
model.addElement(note);

1줄은 메모를 담을 보관 목록, 2줄은 그것을 보여 줄 화면 목록입니다. 3줄은 조회한 메모 한 건(note)을 목록에 넣습니다. 화면에 넣는 것과 DB에 저장하는 것은 다릅니다.

파일과 메서드를 읽는 기준

코드쉽게 풀면
Frame / Panel → DAO화면에서 값을 읽음 → DB 조회·저장을 담당하는 코드에 전달
메서드 / 생성자이름 붙인 처리 과정 / new로 객체를 만들 때 실행되는 준비 과정
reload() / addActionListener(...)목록을 다시 읽어 표시 / 버튼을 눌렀을 때 실행할 일을 연결
setInt(1, teamId)첫 번째 ?에 팀 번호를 넣음. 숫자 1이 팀 번호라는 뜻은 아닙니다.

화면 도구는 Swing(java.desktop), DB 요청은 JDBC(java.sql), 날짜 계산은 LocalDate·YearMonth를 사용합니다. 낯선 이름은 역할부터 기억하세요. 브리핑은 “입력 → 검사 → DB 처리 → 결과 표시” 순서로 설명하면 됩니다.

장*민 · DB와 공통 처리

원래 담당: DB·공통 시스템 / 추가: 데모 준비·공통 기록

내 역할: 프로그램이 사용할 저장소를 준비하고, 로그인한 사람의 소속 팀과 공통 저장 기능을 제공합니다.

시작할 때의 흐름

소스를 읽는 순서

파일시작부터 끝까지 하는 일
Mainmain에서 시작 → 실행 방식 선택 → 연결·표 준비 → 로그인 창 열기
DB_connectionconfigure로 주소·계정 기억 → open으로 실제 연결 만들기
SchemaSetup필요한 표 준비 → 첫 데모이면 계정·팀·예제 생성 → 저장 확정
TeamDAO로그인 회원의 소속 팀 조회 → 사용자가 팀 선택 / 저장 전 소속 검사
ActivityDAO메모·일정 등의 저장 기록 추가 / 현재 팀의 최근 30건 조회

이 값 세 개를 구분하세요

conn은 DB와 연결된 통로, userId는 사람 번호, teamId는 팀 번호입니다. demo1의 회원 번호는 10이고 팀 7 또는 42를 선택합니다. 화면마다 같은 팀 번호를 넘겨야 다른 팀 정보가 섞이지 않습니다.

왜 저장 확정과 취소가 필요한가요?

메모 본문·수정 이력·활동 기록을 묶어 처리합니다. 모두 성공하면 commit으로 확정하고, 하나라도 실패하면 rollback으로 이번 묶음을 취소합니다. 이를 트랜잭션(함께 저장하는 작업 단위)이라고 합니다.

브리핑 한 문장

“저는 DB 연결과 초기 준비를 맡았고, 로그인 회원의 소속을 확인해 선택한 팀 번호를 각 기능에 전달하도록 했습니다.”

이*찬 · 로그인·팀원·공유 메모

원래 담당: 로그인·팀원 관리 / 추가: 공유 메모·수정 충돌 검사

내 역할: 사용자가 누구인지 확인하고, 팀원과 팀이 함께 쓰는 메모를 관리합니다.

소스를 읽는 순서

파일화면 동작에서 저장까지
LoginFrame → UserDAO로그인 클릭 → 빈 입력 검사 → 계정 조회 → 회원 번호·이름 반환 → 소속 팀 선택 → 통합 화면
MemberFrame → MemberDAO팀원 목록 조회 → 등록·수정·삭제 입력 → 계정·소속 표 처리 → 목록 다시 읽기
NotePanel → NoteDAO메모 조회 → 선택·입력 → 제목·소속·버전 검사 → 본문·이력 저장 → 목록 다시 읽기

두 사람이 같은 메모를 고칠 때

메모 화면의 부품

JList는 왼쪽 제목 목록, JTextArea는 오른쪽 내용과 편집창의 긴 글, JOptionPane은 저장·삭제 확인창입니다. Timer는 3초 간격을 알리고, SwingWorker는 화면을 멈추지 않도록 뒤에서 조회하는 작업입니다.

중요한 조건

A와 B가 버전 1을 읽고 A가 먼저 저장하면 DB는 버전 2입니다. B의 “버전 1일 때만 수정” 요청은 처리 행 수가 0이라 취소됩니다. 오래된 내용으로 덮어쓰지 않습니다. 편집창의 글은 자동 갱신으로 바꾸지 않습니다.

팀원 등록·삭제의 차이

등록은 users에 계정을 만든 뒤 team_members에 소속을 넣으므로 두 저장을 묶습니다. 삭제는 해당 팀 소속만 지우고 계정과 기존 담당 업무는 남깁니다.

브리핑 한 문장

“메모의 버전 번호로 동시에 수정했는지 확인하고, 목록 자동 갱신과 편집창 입력을 분리해 내용을 잃지 않게 했습니다.”

윤*훈 · 업무 관리·상태별 목록

원래 담당: 업무 관리 / 추가: 내 업무·메모에서 업무 생성

내 역할: 업무를 등록·수정·삭제하고, 같은 업무를 표·상태별 목록·내 업무로 보여 줍니다.

한 업무가 여러 화면에 보이는 이유

소스를 읽는 순서

파일화면 동작에서 저장까지
TaskFrame입력창 열기 → 업무명·담당자·날짜 검사 → DAO 호출 → 표와 진행률 갱신
TaskDAO현재 팀 조건으로 조회 / 등록·수정·삭제 / 담당자 소속 확인
TaskBoardPanel업무 읽기 → 상태에 맞는 3개 목록에 넣기 → 선택 업무 상태 변경 → 다시 읽기
TaskCardRenderer제목·담당자·마감일을 카드 모양으로 표시. DB 저장은 하지 않음
TaskFromNoteDialog선택 메모로 입력창 열기 → 업무 저장 → 생성된 업무 번호로 메모 연결 저장

화면 부품과 반복문

JTable은 업무 표, JComboBox는 담당자·상태 선택칸, JList는 각 상태의 업무 목록입니다. 상태별 목록은 업무를 하나씩 읽고 “할 일·진행 중·완료” 중 맞는 곳에 넣습니다. 내 업무는 로그인 회원 번호와 담당자 번호가 같은 업무만 읽습니다.

표의 행 번호와 업무 번호는 다릅니다

화면의 세 번째 행이 업무 3번이라는 보장은 없습니다. 선택한 행의 첫 열에 저장된 실제 업무 번호를 읽어 수정·삭제합니다. 팀에서 나간 담당자는 다른 사람으로 자동 변경하지 않고 새 담당자를 선택하게 합니다.

메모에서 업무를 만들 때

업무와 메모 연결이 둘 다 저장돼야 성공입니다. 생성된 번호는 getGeneratedKeys로 받습니다. 연결 저장이 실패하면 업무 생성도 취소합니다. 마감일을 바꾸면 달력도 원본을 다시 읽어 새 날짜에 표시합니다.

브리핑 한 문장

“표와 상태별 목록은 같은 업무를 다르게 보여 주는 화면이고, 상태 변경은 새 업무를 만드는 것이 아니라 기존 업무를 수정하는 것입니다.”

이*주 · 진행률·일정 달력

원래 담당: 일정·진행률 / 추가: 업무 마감일을 달력에 표시

내 역할: 완료 비율과 남은 날짜를 계산하고, 별도 일정과 업무 마감일을 같은 달력에 보여 줍니다.

달력 한 칸을 채우는 흐름

소스를 읽는 순서

파일시작부터 끝까지 하는 일
InlineProgressDAO현재 팀의 사람·업무를 읽어 계산에 필요한 값으로 묶기
InlineProgressData전체·완료 개수 세기 → 비율 계산 / 마감일과 오늘 비교
InlineProgressPanel계산 결과를 JProgressBar(진행 막대)와 마감 안내 글자로 표시
ScheduleDAO별도 일정 조회·저장·삭제 / listDeadlines로 이번 달 업무 마감일 조회
SchedulePanel달력 칸 만들기 → 날짜별 일정·업무 넣기 → 수정 후 또는 탭을 열 때 다시 읽기

계산 예제 두 개

업무 4개 중 완료 1개면 25%입니다. 전체가 0개면 나누지 않고 0%를 표시합니다. 10월 30일~11월 2일 일정은 두 기간이 겹치므로 11월에도 보입니다. 업무는 기간이 아니라 마감일 하루에 표시합니다.

달력을 그리는 기준

첫날이 목요일이면 월·화·수 3칸을 비웁니다. 그달 마지막 날까지 반복하며 날짜가 맞는 내용을 JTextArea(여러 줄 표시칸)에 넣습니다. 오늘은 배경색으로 구분합니다. 완료 업무도 “완료”라고 표시합니다.

업무는 따로 복사 저장하지 않습니다

업무 변경·삭제 후 달력 탭을 열거나 새로고침하면 원본 tasks를 다시 읽습니다. 따라서 예전 마감일에 중복된 일정이 남지 않습니다. 달력의 업무 수정은 업무 관리 화면에서 합니다.

브리핑 한 문장

“달력은 별도 일정과 업무 마감일을 각각 읽고, 날짜가 맞는 칸에 함께 표시합니다. 업무를 일정 표에 복사하지 않아 변경도 원본 기준으로 반영됩니다.”

신*준 · 자료·아이디어·통합 화면

원래 담당: 자료·대시보드 / 추가: 댓글·공감·최근 활동 화면

내 역할: 각 기능을 탭으로 연결하고, 팀원이 자료와 아이디어를 올려 의견을 나누게 합니다.

소스를 읽는 순서

파일화면 동작에서 저장까지
MainFrame로그인한 사용자·팀 받기 → 9개 탭 만들기 → 선택한 탭 다시 읽기
DashboardPanel진행률 계산값·업무·최근 자료 읽기 → 요약 화면 표시
MaterialPanel → MaterialDAO자료명·주소 입력 → 현재 팀·작성자로 저장 → 목록 갱신 / 주소를 브라우저로 열기
IdeaPanel → IdeaDAO아이디어 선택·입력 → 글·댓글·공감 처리 → 목록과 내용 다시 읽기
IdeaCardRenderer / ActivityPanel아이디어를 카드처럼 표시 / 공통 기록 담당 코드에서 최근 활동을 받아 목록에 표시

공감 버튼을 누르면

화면 부품의 역할

JTabbedPane은 여러 화면을 고르는 탭, JList는 아이디어·최근 활동 목록, JTextField는 댓글 입력칸입니다. 렌더러는 목록의 한 항목을 카드로 그리는 코드입니다. 저장과는 역할이 다릅니다.

댓글·공감은 왜 별도 표일까요?

ideas는 글, idea_comments는 댓글, idea_reactions는 누가 공감했는지 저장합니다. 글 번호와 회원 번호를 함께 기본키로 정해 같은 사람의 중복 공감을 막습니다. 글 수정·삭제는 작성자 번호도 검사합니다.

갱신 중에 글을 바꾸어 골라도

5초 간격으로 목록을 다시 읽습니다. 조회 도중 사용자가 다른 글을 선택했다면 새 선택을 유지합니다. 댓글 입력칸은 자동으로 비우지 않습니다. 자료는 파일 자체가 아니라 주소를 저장합니다.

브리핑 한 문장

“화면 표시와 DB 처리를 나누고, 댓글·공감을 별도 표로 관리했습니다. 공감은 삭제된 행 수로 등록과 취소를 구분합니다.”
