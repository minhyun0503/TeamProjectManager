# 먼저 이것만 알고 시작하기

이 프로그램은 **팀원들이 할 일, 일정, 메모, 자료와 의견을 함께 관리하는 프로그램**입니다. 사용자는 버튼을 누르고, 자바 코드는 그 요청을 처리하고, DB는 결과를 기억합니다.

설명서를 읽을 때 처음부터 모든 파일을 외울 필요는 없습니다. 아래 공통 설명을 읽고, 본인 담당 설명에서 버튼 하나를 골라 끝까지 따라가면 됩니다. 그다음 기존의 자세한 설명서로 범위를 넓히세요.

## 실행부터 해 보기

1. Eclipse에서 `src/teamproject/common/Main.java`를 실행합니다.
2. **로컬 데모**를 선택합니다.
3. 아이디 `demo1`, 비밀번호 `demo1234`를 입력합니다.
4. **팀 7**을 선택합니다.
5. 업무 관리에서 업무 한 건을 등록해 봅니다.

`demo2`~`demo5`도 비밀번호는 같습니다. 화면에 아이디(학번)라고 표시돼 있어도 지금은 demo1을 넣습니다. 실제 조원 학번이 아니라 데모 계정을 등록해 둔 상태입니다.

로컬 데모는 같은 컴퓨터의 파일에 저장합니다. 다른 PC의 로컬 데모와 자동으로 연결되는 것은 아닙니다. 여러 PC에서 공유하려면 같은 MySQL 서버에 연결해야 합니다.

## 자주 나오는 말 10개

| 말 | 쉬운 뜻 | 우리 코드에서의 예 |
|---|---|---|
| 클래스 | 관련 데이터와 동작을 모은 코드 단위 | TaskDAO, LoginFrame |
| 객체 | 클래스로 만들어 실제로 사용하는 대상 | new LoginFrame(conn) |
| 메서드 | 이름을 붙여 둔 처리 과정. 다른 코드에서 호출 가능 | login, save, reload |
| 생성자 | new로 객체를 만들 때 처음 실행되는 준비 코드 | LoginFrame(conn) |
| 변수 | 값을 이름으로 구분해 보관하는 곳 | teamId, title |
| 인수·반환값 | 메서드에 보내는 값·처리 후 돌려받는 값 | login에 아이디를 보내고 User를 받음 |
| 이벤트 | 버튼 클릭처럼 프로그램이 처리해야 하는 일 | 로그인 버튼 클릭 |
| DB·테이블·행 | 저장소·정보 종류별 표·한 건의 정보 | tasks 테이블의 업무 한 건 |
| SQL | DB에 조회·저장·수정·삭제를 요청하는 문장 | SELECT, INSERT, UPDATE, DELETE |
| 예외 | 처리를 정상적으로 마치지 못한 상황을 전달하는 방법 | DB 연결 실패 시 SQLException |

## 파일 이름을 보면 역할이 보인다

- **Frame / Panel**: 사용자가 보는 화면과 버튼 동작입니다.
- **DAO**: DB에 어떤 SQL을 보낼지 정합니다. 이름은 Data Access Object의 줄임말입니다.
- **Note / Card / Schedule 같은 작은 데이터 클래스**: 메모 한 건, 업무 한 건의 값을 묶어 들고 다닙니다.
- **Renderer**: JList의 한 항목을 카드처럼 그립니다. 저장 기능은 없습니다.

예를 들어 NotePanel이 사용자에게 글을 입력받고, NoteDAO가 DB에 저장하고, Note 객체가 조회한 글 한 건을 담습니다. 같은 '메모 기능'이지만 맡은 일이 다릅니다.

## 번호는 종류를 구분해야 한다

| 코드의 값 | 실제 뜻 |
|---|---|
| userId=10 | 회원 번호가 10인 사람 |
| teamId=7 | 프로젝트 번호가 7인 팀 |
| taskId=3 | 업무 번호가 3인 업무 |
| version=2 | 메모가 두 번째 저장 상태라는 뜻 |
| setInt(1, teamId)의 1 | SQL에서 값을 채울 첫 번째 빈자리 |

회원 번호와 학번도 다릅니다. user_id는 DB 내부 번호, student_no는 학번 정보, login_id는 로그인에 쓰는 문자열입니다. 데모에서는 login_id가 demo1입니다.

## 화면과 DB는 같은 것이 아니다

화면 표는 DB 내용을 읽어 보여 주는 별도 목록입니다. DB에서 저장했다고 표가 저절로 바뀌지는 않습니다. 그래서 저장 후 `reload()`를 호출해 최신 내용을 다시 읽습니다.

또한 `JList/JTable`은 보이는 화면 부품이고, `DefaultListModel/DefaultTableModel`은 그 부품에 보여 줄 데이터 목록입니다. 메뉴판과 메뉴 내용처럼 구분해서 생각하면 됩니다.

## 브리핑할 때 사용할 문장 틀

“이 버튼을 누르면 **A 메서드**가 실행됩니다. 여기서 **입력값**을 읽고 **조건**을 검사합니다. 정상이라면 **B DAO 메서드**로 전달하고, DAO가 **어떤 표를 어떻게 바꾸는 SQL**을 실행합니다. 성공하면 **화면을 다시 읽고**, 실패하면 **어떤 안내**를 보여 줍니다.”

어려운 단어를 많이 쓰는 것보다, 이 순서를 코드에서 실제로 가리키며 설명하는 것이 중요합니다.
